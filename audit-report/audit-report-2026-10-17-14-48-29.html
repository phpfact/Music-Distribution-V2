What changed

The master-password reset locks and identifies the primary staff account, then updates its password hash and deletes all of its sessions by immutable user ID in one tenant transaction. If revocation fails, the password change rolls back. Other users’ sessions and ordinary username/email edits are preserved.

Changed source: src/lib/tenants/service/tenant-admin.ts

Automatic and manual resets revoke all prior administrator sessions. A forced session-deletion failure rolls back the password change. Fresh credentials still sign in, while unrelated sessions and ordinary admin email edits remain valid.

What changed

Workspace login passes the password hash it verified to createUserSession. Session issuance re-reads the active user under a FOR SHARE lock and compares that hash inside the insertion transaction. A stale hash returns no token and login reports invalid credentials. A reset that waits behind issuance deletes the newly committed session.

How the fix was verified

Controlled PostgreSQL tests cover reset-before-issuance and issuance-before-reset, including a full login paused after old-password verification. Staff and customer stale/missing hashes are refused, as are disabled or missing users.

12 new regression tests passed. Full suite: 61 test files passed; 1,547 tests passed, with one pre-existing skip. Lint, TypeScript and production build passed. Independent read-only security review found no concrete bypass or regression.

Regression coverage: tests/workspace-password-sessions.test.ts. The original audit findings and source excerpts below are historical evidence from the audit snapshot.
