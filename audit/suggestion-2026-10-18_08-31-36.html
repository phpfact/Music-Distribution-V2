Section 1

Executive Summary

Overall project health

Foundation mazboot hai, lekin production ke liye abhi taiyaar nahi.

Yeh project ek multi-tenant music distribution SaaS ki core foundation hai. Tenant isolation, authentication, RBAC aur provisioning ka kaam engineering ke hisaab se kaafi achha hai: har tenant ka alag PostgreSQL database aur least-privilege login hai, tenant sirf Host header se resolve hota hai, sessions tenant aur area se bound hain, aur cross-tenant negative tests maujood hain.

Sabse bade risks operations aur adhoore requirements mein hain. Tenant databases ka automated backup nahi hai, app ka control-plane connection PostgreSQL superuser se chalta hai, koi CI gate nahi hai, aur 16 product decisions open hone se object storage, public tenant signup aur backups ka kaam ruka hua hai. Music distribution ka asli workflow (release submission aur review) abhi shuru nahi hua, jo PRD ke hisaab se expected hai.

    Section 2

    Project Understanding

    Project kya karta hai: Platform Owner apne panel se tenants (organizations) banata hai. Har tenant ko <slug>.<PLATFORM_BASE_DOMAIN> subdomain, apna PostgreSQL database aur alag database login milta hai. Tenant portal mein staff (Master Tenant + Sub-Tenants), customers (artist, label, white-label) aur unke sub-customers hote hain. Teen RBAC domains hain: platform, tenant aur customer. Customers public signup kar sakte hain jise tenant staff ya Platform Owner approve/reject karta hai. Releases, artists, labels, distribution, analytics aur royalties abhi "coming soon" pages hain.

    Tech stack: Next.js 16.4 (App Router, Server Actions), React 19.3, TypeScript 6.0 strict, Prisma 7.10 (do alag schemas), PostgreSQL 18.6, Redis 8.10, MinIO AIStor (sirf phase 1 Docker setup), Tailwind 4 + shadcn/Radix, Argon2id passwords, Docker Compose (dev + hardened prod override), Vitest.

    Size: 378 source files (~57,200 TS/TSX lines), 82 test files (~20,500 lines), 13 migrations (8 control + 5 tenant, 1,581 SQL lines), 21 module memory files .vibe/memory/ mein.

    Ek tenant request ka flow

    1. src/proxy.ts
      Request ID banata hai. /platform/** sirf platform host par, /login, /tenant/**, /customer/** sirf tenant host par; galat host par plain 404.
    2. Host resolution (src/lib/domains/resolve.ts)
      Host header → control plane ki tenant_domains table. Query string, cookie ya X-Forwarded-Host se tenant kabhi nahi liya jaata.
    3. Tenant gate
      Sirf active status + schemaStatus = current wala tenant serve hota hai; suspended/not-ready par friendly page.
    4. Tenant database (src/lib/workspace/context.ts, src/lib/db/tenant.ts)
      Control plane se DB name/login + secrets table ka AES-256-GCM password decrypt, phir size-capped Prisma client cache.
    5. Guard + session (src/lib/workspace/guards.ts, sessions.ts)
      Area-specific cookie → token ka SHA-256 (tenantId:area:token) → user, customer aur single role ek query mein.
    6. Authorization (src/lib/authz/)
      Role privileges minus centrally disabled modules = effective access; mutations par delegation-ceiling policy dobara check hoti hai.
    7. Service + audit
      Transaction ke andar business logic; audit row control plane ki audit_events (append-only trigger) mein.

    Open Questions & Assumptions

    Aapse jaanna hai

    1. Production hosting provider aur base domain (D-1, D-2) kab tak tay honge? Backup ka off-host target isi par depend hai.
    2. Target market India-first hai ya global? Isse phone rule, i18n (Hindi/Hinglish UI), aur aage payouts/tax design tay honge.
    3. Platform Owner MFA ke liye TOTP app chahiye ya passkeys (WebAuthn)?
    4. Transactional email provider ki koi preference hai? (verification, password reset, registration updates)
    5. Custom domains MVP mein feature flag se band rakhne hain ya paid-plan feature ke roop mein scope mein lene hain (C-5, AUD-007)?
    6. Sub-customer sirf 1 level deep hai (DB CHECK). Kya yeh final business rule hai?
    7. Customer profile mein kaun se fields chahiye (contact, address, bank/payout, KYC documents)?
    8. Agle 12 mahine mein kitne tenants aur concurrent users expected hain? Connection strategy aur scale-out isi se tay hoga.
    9. DPDP Act 2023 (India) ya GDPR (EU users) applicable hai? Legal team se confirm karna hoga.
    10. Kin competitors se benchmark karna hai? List milne par Section 6 mein feature comparison jod sakte hain.
